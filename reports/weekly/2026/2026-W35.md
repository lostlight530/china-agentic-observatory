# Lifecycle Correction / 生命周期纠偏
## China AI Weekly Research — 2026-W35 Opening
### Watch window: 2026-08-24 → 2026-08-30

> **From Governable Feedback to Lifecycle Correction**  
> **从可治理反馈，走向生命周期纠偏**

## 0｜Opening Judgment / 开周判断

W34 showed that feedback can become a governed evidence object across quality evaluation, circulation, digital contracts, usage control and fulfillment proof

W35 inherits the final open edge:

> **Can post-use evidence change the next dataset, access, credential or model state?**

The evidence baseline is now strong enough to ask this concretely

- national policy calls for `data-quality validation + model-application feedback` and a data flywheel
- trusted-data-space technical files can monitor use, force termination and emit contract-linked fulfillment evidence
- a public power-sector high-quality-dataset case already describes automatic return of system-recognized data and periodic dataset updates based on model-application feedback

These layers are not yet one unified system

W35 therefore studies the missing lifecycle bridge:

```text
POST-USE EVIDENCE
→ TRACE / CLASSIFY
→ QUALITY + GOVERNANCE REVIEW
→ LIFECYCLE DECISION
→ RECOLLECT / RELABEL / REWEIGHT / RESTRICT / REVOKE
→ DATASET / MODEL / ACCESS STATE CHANGE
→ NEW APPLICATION EVIDENCE
↺
```

## 1｜W35 Working Hypotheses / 工作假设

### H1 — Post-use evidence becomes a formal feedback input

Fulfillment, violation, model-performance and physical-validation evidence increasingly enter later lifecycle decisions

**Falsifier:** mature systems keep post-use evidence permanently separated from dataset/model/access decisions

### H2 — Application evidence triggers explicit data work

Closing the loop requires auditable work items or state transitions such as recollection, relabeling, reweighting, rejection or synthetic generation

**Falsifier:** continuous dataset improvement occurs reliably with no explicit or equivalent lifecycle actions

### H3 — Feedback reuse requires provenance and quality gating

Dynamic interaction data must be traced and filtered for privacy, poisoning, bias, safety, representativeness and task relevance before reuse

**Falsifier:** unrestricted raw feedback reuse proves safe and effective in high-consequence production settings

### H4 — Quality evidence and usage-control evidence require a formal crosswalk

Quality reports, identifier credentials, digital contracts, strategy IDs and fulfillment/termination evidence need stable references if decisions cross platforms

**Falsifier:** large-scale interoperability works without shared evidence references or mappings

### H5 — Termination and violation affect credential/access state

A serious usage-control violation should be able to trigger review, restriction, suspension, revocation or mandatory re-evaluation

**Falsifier:** mature post-use governance treats termination evidence as archival only with no lifecycle consequence

### H6 — Derived outputs inherit governance questions

Derived datasets, trained models, embeddings and Agent outputs may need source-lineage and relevant use restrictions

**Falsifier:** derivatives can always discard source constraints without legal, governance or technical risk

### H7 — Cross-system lifecycle mapping becomes necessary

TC609, TC28, TC591, national dataset services and trusted-data-space mechanisms increasingly need explicit lifecycle crosswalks

**Falsifier:** they remain independent while still supporting auditable end-to-end feedback and reuse

## 2｜Monday Evidence Baseline / 周一证据基线

### National high-quality-dataset policy

The 2026 implementation plan explicitly calls for strengthening `data-quality validation + model-application feedback`, unified evaluation, and a data-flywheel loop driven by application demand and dynamic interaction data

### Trusted-data-space usage control

The published technical file supports behavior monitoring, alerts, forced termination, contract/strategy-linked termination requests and signed fulfillment proofs

### Public power-sector case

A National Data Administration case describes a concrete `collection → labeling → training → application` flywheel, automatic data return, targeted supplementation of rare scenarios and quarterly updates based on model-application feedback

**Boundary:** a documented case is implementation evidence, not a national interoperable standard

## 3｜Research Priorities / 本周优先问题

1. fulfillment / termination evidence → quality evaluation mapping
2. violation → credential/access/contract/circulation state transition
3. application/physical failure → explicit data-construction tasks
4. National Dataset Platform ↔ trusted data space evidence crosswalk
5. TC609 ↔ TC28 ↔ TC591 lifecycle mappings
6. AI training / Agent-specific usage-control profiles
7. derivative dataset / model restriction inheritance
8. more public traceable feedback cases

## 4｜Evidence discipline / 证据纪律

```text
post-use evidence ≠ automatic lifecycle correction
model feedback ≠ safe training data
one case ≠ national interface
termination ≠ automatic revocation
fulfillment proof ≠ quality evidence
quality approval ≠ governance approval
related systems ≠ formal crosswalk
derived output ≠ unrestricted output
```
