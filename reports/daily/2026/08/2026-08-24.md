# Post-Use Evidence Must Return / 使用后证据必须回流
## China AI Daily Research Report / 中国人工智能每日研究报告
### 2026-08-24

**Observation cut-off / 观察截止：2026-08-24 06:46 CST**

## 0｜Executive Judgment / 核心判断

W34 made the feedback lifecycle increasingly governable

Application feedback could enter quality evaluation; quality evidence could become portable; datasets could enter circulation; digital contracts and usage-control policies could constrain post-circulation use; fulfillment proofs could bind execution evidence to exact contract and strategy instances

But W34 ended with one hard gap:

> **Does post-use evidence actually change what happens next?**

W35 opens by connecting three official evidence layers without pretending they already form one unified technical system

1. The National Data Administration’s high-quality-dataset implementation plan explicitly requires **data-quality validation + model-application feedback**, a data flywheel, and use of dynamic interaction data to continuously optimize datasets and model capability
2. The trusted-data-space usage-control technical file can monitor behavior, force termination, and generate contract-linked fulfillment evidence
3. A public high-quality-dataset case in the power sector already describes a `collection → labeling → training → application` data flywheel, automatic return of system-recognized data, targeted supplementation of rare scenarios, and quarterly updates based on model-application feedback

These sources show that post-use evidence can matter to later data work

They do **not** establish a national unified schema connecting fulfillment proof, quality evaluation, credential lifecycle, new data tasks, and retraining

Today’s core judgment is therefore:

> **Post-use evidence must become a lifecycle input, not an archive endpoint**

## 1｜From evidence object to lifecycle action / 从证据对象到生命周期动作

W34 ended here:

```text
APPLICATION / USE
→ TERMINATE OR COMPLETE
→ FULFILLMENT / VIOLATION EVIDENCE
```

W35 asks whether the next state can become:

```text
POST-USE EVIDENCE
→ CLASSIFY / TRACE
→ QUALITY / GOVERNANCE REVIEW
→ REJECT / REWEIGHT / RELABEL / RECOLLECT
→ DATASET UPDATE
→ MODEL ITERATION
→ APPLICATION
↺
```

The right-hand loop remains a research hypothesis, not an official unified architecture

## 2｜Policy already treats application feedback as a data-quality input / 政策已经把应用反馈纳入数据质量

The 2026 high-quality-dataset implementation plan explicitly calls for improving a dual-track method of **data quality validation + model application feedback**

It also calls for a data-flywheel application loop in which application demand pulls data supply and dynamic interaction data generated by model application helps optimize datasets and improve model capability

This supports a durable W35 starting point:

> **Feedback quality is part of dataset quality**

But the plan does not specify a single machine-readable feedback schema or automatic retraining interface

## 3｜Case evidence shows feedback can create concrete data work / 案例证据已经出现反馈驱动数据工作的实例

A National Data Administration high-quality-dataset case for power-operation safety describes:

- a `collection → labeling → training → application` flywheel
- automatic return of system-recognized data
- targeted supplementation of extreme-weather and rare-sample scenarios
- quarterly dataset updates based on model-application feedback

**ANALYSIS** — this is stronger than policy intent because it demonstrates a real application-to-data update mechanism

**BOUNDARY** — it remains one documented case, not proof of a national interoperable feedback interface

## 4｜Trusted-data-space evidence supplies another post-use channel / 可信数据空间提供另一类使用后证据

The published usage-control technical file supports:

- behavior monitoring
- alerts and forced termination for unauthorized or non-compliant use
- termination requests linked to contract and strategy IDs
- fulfillment proofs linked to contract, strategy, log hash, timestamp and connector signature

This means post-use evidence can be both positive (`fulfillment`) and negative (`termination / violation`)

The open question is whether such evidence can be consumed by dataset quality, credential, access, circulation, or retraining systems

## 5｜W35 Opening Hypotheses / W35 开周假设

### H1 — Post-use evidence becomes a formal feedback input

Fulfillment, termination, violation, model-performance and physical-validation evidence increasingly become inputs to later lifecycle decisions

**Falsifier:** mature data/AI systems keep post-use evidence permanently separated from dataset and model lifecycle decisions

### H2 — Application evidence must trigger explicit data work

A closed feedback loop requires auditable actions such as recollection, relabeling, reweighting, rejection, synthetic generation, or new scenario coverage

**Falsifier:** datasets can continuously improve from application feedback without explicit lifecycle work items or equivalent state transitions

### H3 — Feedback reuse requires provenance and quality gating

Dynamic interaction data cannot re-enter training solely because it exists; source, task, privacy, poisoning, bias, safety and representativeness must be evaluated

**Falsifier:** unrestricted raw feedback reuse proves safe and reliable across high-consequence applications

### H4 — Quality evidence and usage-control evidence require a formal crosswalk

Dataset quality reports and post-use contract evidence will need interoperable references if lifecycle decisions are to cross platforms

**Falsifier:** national-platform, trusted-data-space and sector systems interoperate at scale with no shared evidence references or mappings

### H5 — Termination and violation should affect credential/access state

A post-use violation should be able to trigger re-evaluation, access limitation, contract suspension, credential state change, or mandatory review

**Falsifier:** mature governance can treat termination evidence as archival only with no lifecycle consequence

### H6 — Derived outputs inherit governance questions

Derived datasets, fine-tuned models, embeddings and Agent outputs may need to preserve relevant source-data usage constraints or lineage

**Falsifier:** derivative artifacts can always discard source usage conditions without governance or dispute risk

### H7 — Cross-committee lifecycle mapping becomes necessary

TC609 dataset quality/data infrastructure, TC28 embodied systems, TC591 robot validation, national dataset services, and trusted-data-space mechanisms increasingly require explicit lifecycle crosswalks

**Falsifier:** these systems remain independent while still achieving auditable end-to-end feedback and reuse

## 6｜Evidence boundary / 证据边界

- data-flywheel policy ≠ automatic technical feedback loop
- one public case ≠ national interoperable implementation
- fulfillment proof ≠ dataset quality evidence
- termination ≠ automatic credential revocation
- model-application feedback ≠ safe training data
- quality evaluation ≠ governance approval
- published technical file ≠ universal nationwide deployment

## 7｜What to watch this week / 本周优先观察

1. fulfillment / termination evidence → quality evaluation mappings
2. violation → credential/access/contract state transitions
3. application failures → recollection/relabeling/retraining work items
4. National Dataset Platform ↔ trusted data space schema/API crosswalks
5. TC609 ↔ TC28 ↔ TC591 lifecycle evidence mappings
6. AI training / Agent-specific usage-control profiles
7. derivative-data/model restriction inheritance
8. more public cases with traceable feedback rather than only “data flywheel” wording
