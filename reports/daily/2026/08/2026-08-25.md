# Feedback Becomes an Operating Function / 反馈成为运行功能
## China AI Daily Research Report / 中国人工智能每日研究报告
### 2026-08-25

**Observation cut-off / 观察截止：2026-08-25 06:40 CST**

## 0｜Executive Judgment / 核心判断

W35 opened by asking whether post-use evidence can actually change the next dataset, model, credential or access state

Today strengthens the data-construction side of that question

Two National Data Administration public cases now provide complementary implementation evidence

### Power-sector high-quality dataset case

The documented mechanism includes:

- `collection → labeling → training → application` data flywheel
- automatic return of system-recognized data
- targeted supplementation of extreme-weather and scarce-sample scenarios
- quarterly dataset updates based on model-application feedback

### China Mobile high-quality dataset case

The documented platform matrix integrates ten core functions across the dataset lifecycle:

- storage
- aggregation
- processing
- annotation
- synthesis
- evaluation
- management
- retrieval
- supply
- **return / 回流**

It also describes a data-flywheel operating mechanism and dataset-management system

The combined signal is stronger than a policy aspiration alone

> **Feedback return is becoming an explicit operating function inside real dataset infrastructure**

But the evidence still does not justify a national closed-loop claim

> **Return function ≠ standardized feedback semantics ≠ automatic training admission**

## 1｜From feedback evidence to data-construction action / 从反馈证据到数据建设动作

The national implementation plan already establishes the policy direction:

```text
SCENARIO
→ DATA
→ MODEL
→ APPLICATION
→ DYNAMIC INTERACTION / FEEDBACK DATA
→ DATASET OPTIMIZATION
→ MODEL ITERATION
```

Today's case-level evidence adds actual operating actions

Power-sector case:

```text
APPLICATION FEEDBACK
→ AUTOMATIC DATA RETURN
→ IDENTIFY DATA SHORTFALL
→ TARGETED RARE-SCENARIO SUPPLEMENT
→ PERIODIC DATASET UPDATE
```

China Mobile case:

```text
DATA PLATFORM
→ EVALUATE / MANAGE / SUPPLY
→ RETURN
→ DATA-FLYWHEEL OPERATION
```

These are not yet the same schema, platform or lifecycle state machine

## 2｜Why “operating function” matters / 为什么“运行功能”重要

W34 established that post-use evidence can exist

W35 needs to determine whether that evidence produces actual state transitions

Today's evidence moves the answer one step forward because “feedback” is no longer visible only as a report or policy phrase

It appears as:

- automatic data return
- targeted data supplementation
- periodic dataset update
- an explicit platform return capability
- a managed data-flywheel operating mechanism

This strengthens the interpretation that feedback requires durable operational infrastructure

## 3｜What remains missing / 仍然缺什么

Current public evidence still does not show a common machine-readable feedback object such as:

```text
feedback_event_id
source_task
model_version
dataset_version
failure_type
quality_status
required_action
recollection_task
relabel_task
reweight_rule
approval_state
resulting_dataset_version
```

This schema is an observatory illustration, not an official standard proposal

Nor do current cases prove automatic linkage among:

- trusted-data-space fulfillment / violation evidence
- national-platform dataset credentials
- quality evaluation reports
- dataset recollection / relabeling / supplementation
- model retraining

## 4｜W35 Progress / W35 进展

### H1 — Post-use evidence becomes a formal feedback input

**STRONGLY STRENGTHENED**

Policy direction is now complemented by multiple public implementation cases where application/operational data returns into dataset operations

### H2 — Application evidence triggers explicit data work

**STRONGLY STRENGTHENED**

The power case explicitly documents targeted supplementation of rare scenarios and periodic updates based on model feedback

### H3 — Feedback reuse requires provenance and quality gating

**STRENGTHENED / unchanged direction**

China Mobile's platform places evaluation and management alongside return, and national policy requires cleaning, annotation, alignment and quality control; however, public case evidence does not expose the exact per-feedback gating logic

### H4 — Quality evidence and usage-control evidence require a formal crosswalk

**OPEN**

No new public evidence establishes a machine-readable mapping between quality reports, contracts, strategy IDs and returned feedback

### H5 — Termination and violation affect credential/access state

**OPEN**

Today's data-return cases do not show violation evidence automatically changing credential or access state

### H6 — Derived outputs inherit governance questions

**OPEN**

No new evidence resolves how trained models or derived datasets inherit source-data constraints

### H7 — Cross-system lifecycle mapping becomes necessary

**STRENGTHENED**

As return becomes a platform function, the need to map feedback among dataset platforms, trusted data spaces, quality systems and model/application systems becomes more concrete

### H8 — Feedback return becomes an explicit operating function

**NEW / MULTI-CASE IMPLEMENTATION SIGNAL**

Public cases show feedback return as both a concrete dataset-update mechanism and an explicit platform capability

**Falsifier:** further implementations show “return” is only generic data transport with no durable linkage to data-quality, dataset-version or model-iteration decisions

## 5｜Durable rules / 耐久候选规则

```text
feedback evidence ≠ lifecycle action
return function ≠ feedback semantics
automatic data return ≠ automatic training admission
targeted supplementation ≠ auditable work-item schema
quarterly update ≠ continuous automated loop
platform function ≠ national standard interface
two public cases ≠ nationwide interoperable system
```

## 6｜Cross-layer implication / 跨层含义

The W35 lifecycle now has a more concrete data side:

```text
APPLICATION / MODEL
→ FEEDBACK / OPERATING DATA
→ RETURN
→ EVALUATION / MANAGEMENT
→ DATA CONSTRUCTION ACTION
→ DATASET VERSION CHANGE
→ MODEL ITERATION
```

But the governance side remains partially disconnected:

```text
USAGE CONTROL / TERMINATION / FULFILLMENT PROOF
→ ?
→ QUALITY / DATASET LIFECYCLE ACTION
```

That `?` remains one of W35's highest-value research gaps

## 7｜What to watch next / 下一步

1. feedback return producing explicit recollection / relabeling / reweighting task IDs
2. before/after dataset version lineage linked to application feedback
3. returned data passing explicit quality and governance gates before reuse
4. trusted-data-space violation / fulfillment evidence entering dataset lifecycle decisions
5. national dataset services exposing feedback / lifecycle APIs
6. more sector cases with traceable application → data → model state changes
7. embodied physical-validation failures generating explicit new collection/simulation actions
8. derived-model restrictions after source-data contract changes
