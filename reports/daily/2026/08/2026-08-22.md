# Contract Produces a Proof / 合约开始产生履约证明
## China AI Daily Research Report / 中国人工智能每日研究报告
### 2026-08-22

**Observation cut-off / 观察截止：2026-08-22 10:47 CST**

## Executive Judgment / 核心判断

昨天 W34 已经把数据流通后的持续治理拆成数字合约、使用控制策略、行为校验与受控操作

今天继续追问：**策略到底有没有被执行，执行完成或中止后能留下什么证据**

《可信数据空间 使用控制技术要求》的公开技术文本已经给出非常具体的接口语义：

- 中止请求包含 `terminationId`、`contractId`、`strategyId`、中止原因、触发方和时间戳
- 完整执行数字合约后，数据使用方接入连接器生成履约证明并发送给数据提供方连接器和可信数据空间服务平台
- 履约证明包含 `proofId`、`contractId`、`strategyId`、`logHash`、可选区块链交易 ID、时间戳以及连接器签名
- 使用环境还要求隔离、环境完整性，以及对算法模型、应用程序、插件进行可信认证或数字签名校验

这使昨天的链条进一步变成：

```text
DIGITAL CONTRACT
→ USAGE-CONTROL POLICY
→ POLICY EXECUTION
→ BEHAVIOR / ENVIRONMENT EVIDENCE
→ TERMINATE OR COMPLETE
→ FULFILLMENT PROOF
→ PROVIDER / PLATFORM
→ COMPLIANCE / SETTLEMENT / FEEDBACK
```

今天因此可以形成一个更强判断：**post-circulation governance 已经不仅有“规则”，还开始有可关联合约、策略和日志摘要的执行证据模型**

但边界必须继续守住：

> **Fulfillment proof ≠ proof of semantically correct use**

一个签名的履约证明可以说明某个连接器声明某合约 / 策略执行完成，并绑定日志摘要；它并不能自动证明数据使用目的合理、模型输出安全、衍生数据没有越界，或所有可信数据空间已经统一实现该接口

## 1｜From contract to evidence / 从合约到证据

昨天主要是：

```text
contract
→ policy
→ execution
```

今天加入：

```text
contractId / strategyId
→ execution trace
→ logHash
→ connector signature
→ fulfillmentProof
```

这使数字合约第一次在本仓模型里拥有可审计的 post-execution artifact

## 2｜Termination is a separate path / 中止是独立路径

技术文本显式定义 termination request，并保存触发方、原因和时间

这意味着治理不只有“完成 / 不完成”，还需要回答：

- 谁中止
- 为什么中止
- 中止了哪个合约和策略
- 中止发生在什么时候
- 中止是否会影响后续 credential / circulation / feedback

## 3｜Environment trust enters usage control / 使用环境进入控制边界

使用控制文件还把执行环境隔离、完整性验证和组件签名校验纳入安全要求

因此“合约有效”与“执行环境可信”不能合并

```text
valid contract
≠ valid environment
≠ compliant execution
≠ correct outcome
```

## 4｜W34 Saturday Judgment / 周六判断

今天新增：

> **H11 — Fulfillment evidence becomes a post-circulation governance object**

### Falsifier
