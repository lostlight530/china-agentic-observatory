# The Network Becomes the Substrate / 网络成为智能体底座
## China AI Daily Research Report / 中国人工智能每日研究报告
### 2026-08-10

**Observation cut-off / 观察截止：2026-08-10 05:49 CST**

## 0｜Executive Judgment / 核心判断

今天没有发现 8 月 10 日凌晨发布、足以推翻昨日“标准之桥”判断的 C0/C1 级新文件

但把近期三份官方材料重新放到同一结构里后，中国智能体路线向下延伸了一层：**从国家互联标准、可信身份与网关规范，继续走向通信网络、IPv6 标识和云网边端基础设施**

最关键的两个事实是：

第一，7 月 21 日发布的《深化互联网协议第六版（IPv6）技术创新和融合应用实施方案（2026—2030年）》明确提出推动 IPv6 与智能体应用融合，并“探索基于 IPv6 的智能体标识技术”

第二，6 月 11 日公布的《“人工智能+信息通信”创新发展实施意见（2026—2028年）》明确提出加强网络智能体创新发展，突破多智能体协同、智能体通信等技术，“打造自主智能体通信协议”，并推动智能体云化部署

这两个措辞必须严格校准：**探索标识技术 ≠ 已形成 IPv6 智能体标识标准；打造通信协议 ≠ 已发布统一协议**

今天的结构性判断是：

> 中国智能体体系正在出现“应用层互联标准 + 可信授权层 + 网关协同层 + 网络基础设施层”同时推进的迹象

### English

No same-day C0/C1 release before the cut-off overturns yesterday's standards-bridge judgment. But recent official documents reveal a lower layer of the architecture: China's agentic system is extending from application-level interconnection standards and trusted authorization toward communications networks, IPv6 identity exploration, and cloud-network-edge infrastructure.

The status boundary is essential. “Explore IPv6-based agent identification” is not a finished identity standard, and “build an autonomous agent communication protocol” is a policy task, not a released protocol.

## 2｜IPv6 brings identity into the network layer / IPv6 把身份问题推向网络层

**OFFICIAL FACT** — 2026—2030 IPv6 实施方案提出推动 IPv6 与智能体应用融合发展，并探索基于 IPv6 的智能体标识技术

**ANALYSIS** — 昨天的身份问题主要存在于 GB/Z 185 身份码、身份管理、ASL 可信身份与国际 Agent interoperability 语境中。今天加入 IPv6 后，身份首次明显下沉到网络基础设施研究面

这意味着未来可能需要回答：

```text
应用层 Agent 身份码
↕
可信身份 / 授权主体
↕
网络可寻址与标识
↕
云 / 边 / 端实际运行主体
```

目前没有足够证据证明这些层已经实现统一映射

## 3｜Telecom policy treats agents as network-native engineering objects / 信息通信政策开始把 Agent 当作网络工程对象

工信部 2026—2028 信息通信实施意见提出：

- 研发专业性强的网络大模型和智能体
- 突破大小模型协同、多智能体协同、智能体通信
- 打造自主智能体通信协议
- 探索基于智能体的新型电信业务形态
- 构建网络智能体自主产业生态
- 推动智能体云化部署
- 在网络设备中部署智能算力
- 推进云网边端协同推理

**ANALYSIS** — 这里的 Agent 已经不只是使用通信网络的应用，而开始成为网络运营、网络服务和网络基础设施自身的设计对象

## 4｜The standards bridge now has a substrate / 标准之桥开始出现底座

昨日结构：

```text
GB/Z 185
→ ASL
→ AIIA 协同 / 网关
→ ITU-T 国际互操作
```

今日补充：

```text
GB/Z 185 身份 / 发现 / 交互 / 工具调用
→ ASL 可信身份 / 意图 / 授权
→ AIIA 多智能体协同 / 网关
→ IPv6 智能体标识探索
→ 自主智能体通信协议任务
→ 云网边端 / 网络设备 / 电信业务
→ 国际互操作与生命周期治理
```

这不是一个已经完成的统一技术栈，而是一组正在接近的政策、标准与工程层

## 5｜Workstream Findings / 分任务发现

### C1 History and policy / 历史与政策

2017 国家战略 → 2025 AI+ → 2026 智能体实施意见的路线正在进一步进入信息通信与 IPv6 专项政策，说明 Agent 正从通用 AI 政策对象变为具体基础设施对象

### C2 Standards and protocols / 标准与协议

GB/Z 185 仍是现行国家互联基线；ASL 与 AIIA 继续补充可信授权、协同与网关；IPv6 标识和自主通信协议目前只能标记为探索/任务状态

### C3 Research and models / 科研与模型

今天没有模型层新事实足以改变长期判断。网络智能体路线反而说明模型必须与通信、设备、云边端推理和行业数据共同观察

### C4 Agents and open source / 智能体与开源

后续国内开源 Agent 项目的重要观察点将不再只是 skill、memory、workflow，而是是否出现 identity、gateway、network transport、audit 与 protocol mapping 层

### C5 Infrastructure and industry / 基础设施与产业

今天最强变化发生在这一层：Agent 被明确放进 IPv6、通信网络、网络设备、智算云与云网边端协同场景

### C6 Applications and governance / 应用与治理

网络级 Agent 一旦拥有配置、调度、优化和安全防护能力，其权限边界、操作审计和人工接管将比普通聊天服务更关键

### C7 China–Global / 中外路线

中国路线正在同时推进“身份—网络—通信协议—产业部署”，而国际 MCP/A2A 更典型地从应用协议和跨厂商互操作出发。两者比较必须落到具体层，不应直接称为同一类协议竞争

## 6｜Changed Judgments / 判断修正

### 新增判断

“身份”不能只在协议和治理层观察，本仓必须加入**网络标识与基础设施身份**这一维度

### 强化判断

中国 Agent 体系可能形成多层标准结构：国家互联语义、可信授权、安全网关、网络标识、通信协议、云网边端部署分别由不同机制推进

### 保留限制

目前没有证据证明这些层已经形成统一架构或实际全国部署

## 7｜Stable Judgments / 稳定判断

- 政策任务不等于实现
- “探索”不等于标准发布
- “打造协议”不等于已有正式协议正文
- 国家标准不自动证明跨厂商互操作
- 产业联盟研讨不等于国家标准
- 网络 Agent 与通用 Agent 协议需要按层比较

## 8｜Uncertainties / 不确定项

1. IPv6 智能体标识最终采用地址、标识、身份凭证还是映射机制
2. 自主智能体通信协议是否形成独立规范
3. 它与 GB/Z 185、ASL、MCP、A2A、ITU-T F.748.93 如何映射
4. 网络设备内 Agent 的权限模型和人工接管机制
5. 运营商、云平台与终端是否会共享统一 Agent 身份体系
6. 是否出现公开互操作、测试或部署证据

## 9｜Watchlist / 下一轮观察点
